# Текущее состояние

## Active objective

Сделать ответы по визуальным рабочим инструкциям самодостаточными для неподготовленного
пользователя: сохранить реальные ссылки из Word, показать их кликабельно и выдать полный путь от
подготовки до проверки результата без догадок и подмены URL номером источника.

## Acceptance criteria

- [x] DOCX extractor сохраняет подпись и точный target внешних `http`, `https` и `mailto`-ссылок,
  удаляет дубликаты и не переносит небезопасные схемы.
- [x] Ссылки попадают в индексируемый контекст как данные документа, в том числе при visual
  ingestion, и доступны модели вместе с пошаговыми chunks.
- [x] Контракт генерации требует подготовку, атомарные шаги, точные названия элементов, ожидаемый
  результат, проверку завершения и доступный путь помощи; `[N]` не подменяет реальный URL.
- [x] Реальные `http`/`https` URL в ответе безопасно отображаются кликабельными; произвольный HTML
  ответа не исполняется.
- [x] После повторной индексации ответ на «Настройка VPN VMware VPN Client» содержит точную ссылку
  на архив либо явно сообщает, что адрес отсутствует, и доводит пользователя до проверки VPN.
- [x] Целевые тесты, полный `make test`, `make lint` и browser QA проходят.

  и страницы 1–4 вместо прежних 11 visual-only chunks.

  console errors.

## Changed areas

- Изменены DOCX extraction, visual context expansion, parsing/quality guarantees ответа,
  безопасный URL renderer, стили, документация и unit/runtime/API tests.

## Decisions made

- URL извлекается детерминированно из структуры DOCX, а не распознаётся со скриншота и не
  придумывается моделью.
- Ссылки остаются частью недоверенного контекста: разрешены только ожидаемые схемы, UI строит DOM
  anchors самостоятельно и не использует HTML модели.
- Если в документе нет критически важного адреса, ответ обязан назвать пробел и доступный канал
  помощи, а не имитировать ссылку citation-номером.
